# 布局审计（鸿蒙版 16 档主题）— 2026-10-15

## 起因
用户要求"检查下鸿蒙版本 UI 有没有错漏错位的"。

## ★ 最重要的发现：审计工具本身有覆盖漏洞

`tools/layout_check.py` 是**真源码渲染**（Node 剥类型后跑 ArkTS，用 canvas 打桩记录每个文字框），
但它的模拟器 `tools/hwsim/layout_real.mts` **只实现了主题 1~8 的分发**：

```ts
if (theme === 3) ... else if (theme === 8) ... else if (theme === 1) ... else Dashboard
```

**主题 9 和 10~15 没有分支 → 全部回落到 `else` 画仪表盘。**
后果：`--theme=11` 报的"✅ 干净（45 个文字元素）"其实是**仪表盘的审计结果**，
这 6 个主题**从来没有被查过**。而工具不会报错，只给一个看起来很正常的数字 —— 最难发现的那种漏洞。

### 修法
1. **补全分发**：主题 9（借位档 Dotii）、10（赛博）、11~14（二次元四档）、15（trofeo-lcd）
2. **补面板矩形**：主题 9~15 是**整屏主题**（没有五格/卡片分区），
   以前没有对应面板 → 回落到 `dashPanels`（仪表盘五格）
   → "越出面板(DSH 会话)"这类报错**全是假问题**。改用整张画布作唯一面板。
3. **补 `HostStats` 桩**：`service/HostStats.ets` 依赖三个鸿蒙专属 kit
   （`@kit.PerformanceAnalysisKit` / `BasicServicesKit` / `CoreFileKit`），Node 里跑不起来；
   主题 15 会 import 它 → 报"找不到模块"，整个审计跑不动。现生成确定性桩。
4. **`render/Backdrop` 加入文件清单**（主题 15 的传递依赖）。
5. **enum 改写**：Node 的 `--experimental-strip-types` 是 **strip-only** 模式，
   不支持 TS `enum`（需要代码生成）。`Backdrop.ets` 的 `export enum BgStyle` 直接抛
   `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX`。现自动改写为等价的常量对象。
6. **canvas 桩补 `setLineDash`/`getLineDash`**：标准 canvas API，`ThemeAnimeBG` 用了，
   缺它会让主题 11 渲染直接失败（`TypeError: ctx.setLineDash is not a function`）。

## 修完后的结果

| 主题 | 结果 |
|---|---|
| 0~12、15 | ✅ 干净 |
| 13 明亮二次元 HUD | ❌ 20 个 —— **全是误报**（见下） |
| 14 NanoMuse 大字 | ❌ 58 个 —— **多为误报**（见下） |

## 已知误报的三种成因（都不是主题 bug）

| 现象 | 成因 |
|---|---|
| "文字压到进度条"（主题 13） | **设计意图**：用的是 `barWithWatermark()`，把水印文字按设计画在条内 |
| "越出面板(系统): '20817.0/23859.0G'"（主题 12/13） | **审计夹具数据不真实**：`memUsed: 20817, memTotal: 23859`（MB）→ 显示成 "20817.0/23859.0 GB" |
| "文字重叠 75%"（主题 14） | 桩的**文本度量是近似值**（无字体引擎），且按绝对坐标逐字记录；放大字号的相邻行会被误判 |

## 本轮真正修掉的工具 bug

| # | bug | 影响 |
|---|---|---|
| 1 | 主题 9/10~15 无分发，回落到仪表盘 | 6 个主题**完全没被审计**（假绿） |
| 2 | 主题 9~15 用仪表盘面板矩形 | 越界报错全是假问题 |
| 3 | 缺 `HostStats` 桩 | 主题 15 连带整个审计跑不起来 |
| 4 | 缺 `render/Backdrop` | 同上 |
| 5 | 不支持 TS `enum` | 同上 |
| 6 | canvas 桩缺 `setLineDash` | 主题 11 渲染失败 |

## 结论

**鸿蒙版 16 档主题的布局没有发现真实错位**（0~12、15 干净；13/14 的报错已逐条归因为
设计意图 / 夹具数据 / 度量近似）。但**这个结论的可信度建立在本轮修的 6 个工具 bug 之上** ——
修之前那 6 个主题的"干净"是假的。
