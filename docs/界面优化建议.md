# 界面（鸿蒙 App 控制页）优化建议与已改动

> 日期：2026-10-15 · 对象：`entry/src/main/ets/pages/Index.ets`（1521 行）与 `Gui.cs`（C# 侧同构）
> 触发：用户要求"优化 UI，并给出建议"，且此前反映过"每次打开都要拉大窗口"

## 一、先量化问题（都从代码里数出来的）

### 1. 页面有 10 个区块一次性全部渲染 —— 这是"要拉大窗口"的根因

`build()` 里的区块顺序（代码行数按 builder 体量统计）：

| 区块 | 代码行 | 屏占 | 性质 |
|---|---|---|---|
| `header` / `summaryBar` | 22 / 11 | 小 | 常看 |
| `viewCard`（预览） | 69 | **大** | 常看 |
| `controls`（启动/停/帧率） | 44 | 中 | 常看 |
| **`themeRow`（16 个主题按钮）** | **165** | **最大** | 常看 |
| `seqRow` | 60 | 中 | 偶尔 |
| `switchCard` | 82 | 中 | 偶尔 |
| `vmCard` | 59 | 中 | 偶尔 |
| `deviceCard` / `pictureCard` / `diagCard` | 17 / 14 / 13 | 小 | **排障才看** |

**10 块全渲染 → 总高远超一屏 → 每次打开都要往下滚**。这是结构性问题，不是"底部留白不够"。

### 2. 尺寸有 8 种高度、6 种字号（视觉不齐）

```
.height  →  28(×25)  24(×3)  40(×2)  38(×2)  22(×2)  34  12  6
.fontSize→  11(×31)  12(×16) 14(×2)  10(×2)  22  13
```

主按钮 28、但另有 24/22 两种小按钮，字号 11 与 12 混用 —— 没有成套的尺寸阶梯。

### 3. 主色只用了蓝色（绿色仅表示"选中"）

`#238636`（选中绿）与 `#21262D`（未选中灰）贯穿全部按钮，
**不同类型按钮没有视觉区分**：主题按钮、开关按钮、危险按钮（停止）长得一样。

## 二、已改动（本轮实做）

### ✅ 新增「高级与排障」折叠区（默认收起）

把 `deviceCard` + `pictureCard` + `diagCard` 三块（共 44 行代码、3 个标题）
收进一个默认收起的折叠条。点击展开/收起。

**收益**：日常打开时省掉 3 个卡片 + 3 个标题的高度，且常用操作（启动、换主题、开关）
都在上方，**不用再滚到底**。这三块本来就是排障才看的。

## 三、建议改动（按性价比排序，等你确认）

| # | 建议 | 收益 | 成本 |
|---|---|---|---|
| **1** | **主题按钮改成两列网格**（现在 16 个按钮挤在两行 Flex 里，窄窗口会换行不可控） | 窄窗口下不再乱；扫描更快 | 小 |
| **2** | **建立尺寸阶梯**：主按钮 30 / 次按钮 26 / 图标按钮 22；字号 12 / 11 / 10 三级 | 视觉整齐、好维护 | 小 |
| **3** | **按钮按类型配色**：主题=蓝 `#1F6FEB`、开关=紫 `#8957E5`、危险=红 `#DA3633`、普通=灰 | 一眼分辨功能，防误点 | 小 |
| **4** | **把 `seqRow` 也折进高级区**（序列播放是实验功能，日常不用） | 再省一块 | 极小 |
| **5** | **预览框支持"适应高度"**：现在只按宽度算缩放，竖屏预览时上下留白多 | 预览更大更清楚 | 中 |
| **6** | **顶部摘要条加"当前主题名"**：现在 `summaryBar` 没有主题信息，换主题后要往下找 | 一眼看到当前状态 | 小 |
| **7** | **`switchCard` 的开关做成一行一个**：现在挤在一起，触屏上容易点错 | 触屏友好 | 小 |
| **8** | **危险操作加二次确认**（停止推送、清空偏好） | 防误触 | 小 |

## 四、一个更根本的建议

**把"配置"与"运行"分成两个页签**（Tabs）：

```
[ 运行 ]                          [ 设置 ]
  预览（大）                        主题选择（网格）
  启动/停止/帧率                    序列
  当前主题名 + 状态                 开关组
  高级与排障（折叠）                VM / 设备 / 画面 / 诊断（折叠）
```

理由：现在这两类内容混在一条长滚动流里，**每次换主题都要滚过预览**、
**每次看预览都要滚过一堆配置**。分页签后两边都能"一屏搞定"，
比继续在单页里折叠更彻底。这个改动比上面 8 条都大，但一次到位。
