## 三、我自己做的优化 + 自查（已完成的部分）

### 3.1 字体"虚"：找到两个真因，都已处理

| 根因 | 处理 | 实测 |
|---|---|---|
| **JPEG 质量 0.85 + 字号偏小**（Dotii 档状态栏只有 24px，1 逻辑像素只落 0.54 屏像素） | 字号提到 32～40px；文字型主题 JPEG 质量提到 **0.95** | 文字边缘梯度中位 **45 → 64**、90 分位 **139 → 157** |
| **推帧高度 462 vs 480**（面板规格 480；固件内部 FB 是 480、玻璃约 468 → 推 462 会**双重缩放**，这是发虚的另一大来源） | 加了运行时开关 `/set?frh=480`（0=回握手值），改完会重建校准 | **待实测**：构建时整机内存耗尽，未上屏 |

判定锐度的现成方法（不需仪器）：

```python
from PIL import Image
im=Image.open('frame.jpg').convert('L'); px=im.load()
e=[abs(px[x+1,y]-px[x,y]) for y in range(30,440,2) for x in range(790,1130)]
e=[d for d in e if d>10]; e.sort()
print(len(e), e[len(e)//2], e[int(len(e)*0.9)])   # 中位/90分位，越大越锐
```

### 3.2 配色：解决了"纯蓝看不见"的硬问题

本机 JPEG 是 **4:2:0 色度抽样**（SOF0 `[C1 2x2]`），**纯蓝 `#0000FF` 解码后几乎归零、纯青 `#00FFFF` 归零**
—— 固件那套饱和 RGB565 色直接照抄就丢色。已做**源色预补偿**：

```
砖块 5 色：红 #FF0000→#F01010  橙 #FFA500→#F0A018  黄 #FFFF00→#F0E828
          绿 #00FF00→#20E020  蓝 #0000FF→#3A55E0
配色类：cyan #00FFFF→#30D8E0  blue #319AFF→#4AA0F0  track #191C19→#20261F …
```

**实测蓝砖像素 0 → 1362**。代价：与固件 RGB565 原值有数值偏差（观感更接近原意）。
`/set?fws=100` 留了色卡标定页，随时可复测。

### 3.3 漏光补偿（你说的右下角漏光）

`Chrome.vignette()`：椭圆径向渐变，按**旋转后**的物理角定位。
**踩过一个坑**：整帧推之前有 180° 旋转，所以"缓冲区右下角"在物理屏上是左上角 ——
第一版正好压反（实测左上 −13.9、右下 0.0）。修正后：

| 强度 | 物理右下（漏光处） | 物理左上 | 中心 |
|---|---|---|---|
| 关 | 24.0 | 20.3 | 40.8 |
| 45% | 18.6（**−5.3**） | 20.4（+0.1） | 41.9 |
| 70% | 15.6（**−8.3**） | 20.5（+0.2） | 41.2 |

调法：`/set?vig=0..100`（0=关）、`/set?vigreach=N`（半径）。

### 3.4 帧率：实测天花板 ≈ 8fps（并留了两道安全护栏）

- 每帧：render 2 + encode 48～65 + push 47～80 ≈ **110ms**，**串行流水线**是瓶颈
- 间隔从 500ms 压到 17ms，fps 只从 3.8 → 7.1
- **踩过的大坑**：帧内并发 USB 写（`wbatch>1`）会**撕裂分块流** → 屏花屏 → **卡在开机画面**，
  应用侧 `bulkTransfer -1`；`wsize=8192` 同样打死 HAL。恢复只能**拔屏的 USB 线断电**
- 已钉死：`MIN_PUSH_INTERVAL_MS=120`、`writeBatch=1`、`wsize≤4096`
- 协议层面 60Hz 不可达（固件解码约 1s/100KB、不支持原始帧/局部刷新；官方软件自己只有 15/24fps 档位）

## B. 屏为什么不在线（一手日志）

```
deviceLabel    = USBDISPLAY (416:5408)   ← 屏在 USB 总线上、描述符完整
claimInterface iface=0 ret=-1            ← 接口被占，应用拿不到
bulkTransfer 返回 -1（驱动异常）
```

- **不是代码问题**：设备描述符读到了、端点认出来了（OUT=0x9 / IN=0x81）
- 成因链：主题轮播被设成 **1 秒** → 每秒重渲染+编码+推帧 → 帧循环从 125ms 恶化到 **3895ms**
  → 应用卡死 → 强杀 → `close()` 来不及跑 → 接口残留在内核
- **恢复动作：拔插一次屏的 USB 线**（杀进程、重启应用、`/set?usbreset=1`、hub 级复位全试过，都无效）
- 顺带改进：新增 `usbClaimBlocked` 字段，`lastError` 现在直接写
  "USB 接口被系统占用（claimInterface=-1）：请拔插一次屏的 USB 线"，一眼可见
