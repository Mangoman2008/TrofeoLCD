## 二、NanoMuse 实测设计令牌（已从 `dist/index.html` 提取）

它是**单文件**主题（HTML+CSS+JS 共 310KB），有明暗两套。

### 2.1 明亮版（"白瓷片"）
```css
--bg:        #eaeff6      /* 冷白底 */
--cyan:      #00b8d4      /* 主强调（青） */
--blue:      #0096c7      /* 次强调 */
--t:         #1a2c3e      /* 主文字（深蓝灰） */
--g:         #00e676      /* 正常 */  --r: #ff3d57 /* 危险 */  --am: #ffab00 /* 警告 */
--card-bg:   rgba(242,248,255,0.74)   /* 卡片：**半透明白玻璃** */
--glass:     rgba(240,246,255,0.72)
--border:    rgba(180,205,225,0.35)
--glow:      0 0 24px rgba(0,184,212,0.18)   /* 青色柔光 */
--grid-color:rgba(20,90,140,0.04)            /* 极淡网格 */
--corner-color:rgba(0,170,210,0.65)          /* HUD 切角 */
--rail:      rgba(0,150,190,0.40)            /* 进度条轨道 */
```

### 2.2 暗色版
```css
--bg:   #14272d      /* 深青黑（注意：不是纯黑，是带绿的深青） */
--cyan: #00e5e0      /* 亮青 */
--blue: #4ff5f0
```

### 2.3 它的版面语言（README 原文 + 令牌推断）
- **白瓷片材质卡片** —— "整洁大方，呼吸感强"（`--card-bg` 74% 白 + 1px 淡边 + 青色柔光）
- **三栏 Hero 区** —— 左：Fleet Status / Load / Bandwidth；中：**角色透出 + 粒子**；右：Realtime / Network / Ping
- **节点健康度圆环** —— 每卡一个 Health 值（CPU/RAM/DISK 综合）
- **进度条内嵌硬件配置** —— CPU Cores / RAM / Disk 以**水印风格**嵌在进度条里
- **三列底栏** —— UPTIME / TX / RX
- **角色渐显动画** —— 4.5s `blur → 清晰`（`charReveal`）
- **电路线 SVG 背景** —— 折角走线 + 渐变 + 箭头标记
- **原生 Canvas 图表**（真实时间轴、跨天显示日期）

### 2.4 可迁移到我们屏上的 5 个手法
| 手法 | 我们的落地方式 |
|---|---|
| 白瓷片半透明卡 | 明亮版主题：卡片 `rgba(255,255,255,0.74)` 压在图/渐变上，1px 淡边 + 青色柔光 |
| 健康度圆环 | 已有（主题 8 的弧表），改成它的"综合健康值"语义 |
| 进度条内嵌水印配置 | 进度条上叠一层 20% 透明的 `CPU 14核 / RAM 23.3G` 文字 —— 省版面又好看 |
| 角色透出 | **我们下不了图** → 程序画一个 Q 版侧影/剪影（纯几何能做出轮廓感） |
| 电路线背景 | 折角走线用 `moveTo/lineTo` + `createLinearGradient` 描边，成本低 |

## 三、AcgUI 的 6 个特效（MIT，可直接实现）

| 组件 | 描述 | 参数 | 我们的实现要点 |
|---|---|---|---|
| **Sakura** 樱花飘落 | 粒子效果 | 密度/速度/颜色 | 已实现（主题 12）；按它的参数化思路暴露 density/speed/color |
| **Bubble** 气泡上升 | 上升动画 | 密度/速度/颜色 | `arc` + 上升位移 + 半透明描边圆 |
| **Border** 动态边框 | 边框沿线绘制 | 速度/颜色/线宽 | 用"路径分段 + 逐帧增加已绘长度"模拟（canvas 无 dashoffset） |
| **Star** 星星闪烁 | 闪烁 | 颜色/位置/大小 | 已实现 |
| **Background** 背景切换 | 图片列表 + 切换时长 | 图列表/时长 | 我们下不了图 → 改成"**渐变方案轮换**"（12 套预设色，交叉淡入） |
| **Breathing** 呼吸 | 元素呼吸闪烁 | 速度/颜色 | `globalAlpha` 4 档量化（8fps 友好） |

**唯一有实现难度的**是 `Border`（动态边框）。Canvas 没有 `strokeDashoffset`，
但可以用"把路径按长度分段，逐帧只画前 N 段"实现——工程里已有 `moveTo/lineTo` 基础，成本可控。

## 四、4:2:0 硬约束（这两套配色都踩线，必须预补偿）

本机编码器是 **4:2:0**（实测 `#0000FF` 屏上几乎归零、`#00FFFF` 屏上 0 像素）。
而这两套项目的主色**恰好都在危险区**：

| 原色 | 来源 | 风险 | 建议补偿值 |
|---|---|---|---|
| `#00b8d4` | NanoMuse 明亮版主色 | 青，G/B 远高于 R → **色度会被砍** | `#30B0C8` 一类（压低 G、抬 R） |
| `#00e5e0` | NanoMuse 暗色版主色 | 同上 | `#30D8E0`（**本工程已实测可用**） |
| `#00e676` | NanoMuse 正常色 | 纯绿 | `#20E020`（**已实测可用**） |
| `#ff3d57` | NanoMuse 危险色 | R 贴顶 | `#F0405F` |
| `#0096c7` | NanoMuse 蓝 | 偏纯 | `#4AA0F0`（**已实测可用**） |

**已有可复用补偿对**（来自 `HANDOFF-打印机格复刻.md §6.4` 第一手实测）：
`#00FFFF→#30D8E0`、`#0000FF→#3A55E0`、`#00FF00→#20E020`、`#FF0000→#F01010`、`#00AE42 可用`

**规则**：结构（线/字/图标）靠**亮度差**表达；饱和色只出现在 **≥24×24 的块**或 **≥3px 粗线**上。

## 五、建议做的两个方向（本屏 1920×462）

### 方向 甲 ·「明亮二次元 HUD」（照 NanoMuse 的语言）
- 冷白渐变底 `#EAEFF6 → #DCE6F2` + 极淡网格（`rgba(20,90,140,0.04)`）
- **白瓷片半透明卡**（`rgba(255,255,255,0.74)` + 1px 淡边 + 青色柔光）
- 深蓝灰文字 `#1A2C3E`（浅底上用深字，**彻底解决"字看着虚"**）
- 青色 HUD 切角 + 电路线背景 + 健康度圆环
- 中间留一块"角色透出"区（程序画 Q 版剪影）
- **优点**：与现有 12 个深色主题形成互补；浅底在浅色桌面上更耐看；文字对比度最高
- **风险**：亮底在桌面旁可能偏抢眼；4:2:0 对浅底反而更安全（色度信息少）

### 方向 乙 ·「电子二次元（暗）」= NanoMuse 暗色版
- 深青黑底 `#14272D`（不是纯黑，带绿的深青，比现有主题更有"电子感"）
- 亮青 `#30D8E0`（补偿后）+ 柔和网格 + 玻璃卡
- 结合 AcgUI 的气泡/呼吸/动态边框
- **优点**：与现有深色主题连贯，改动小
- **风险**：与主题 10（赛博二次元）有重叠感

## 六、待办与限制（如实记录）

1. **未取得**：NanoMuse 的许可证未在仓库标注 → 若要用它的**代码**需先确认；目前只**借鉴设计语言与令牌数值**（不复制代码）
2. **资源限制**：两套项目都依赖**图片素材**（角色图 / RMSKIN 位图 / 字体文件）。本机**下载通道受限**
   （wallhaven 被墙、Unsplash API 要 key、Bilder 源 503），且本屏**不能引入外部字体** →
   所有"角色/图片"部分只能**程序化绘制**或由用户提供图片
3. **碧蓝档案那套是 CC BY-NC-SA 4.0**：**非商用** + 相同方式共享 → 不能把它的资源（字体/位图）打进我们的应用
4. **未验证**：AcgUI 的 `Border`（动态边框）在无 `strokeDashoffset` 的 Canvas 上的实现效果需实测
5. **未验证**：`#00b8d4` 的补偿值（`#30B0C8`）**没有上屏实测过**，需要用主题里的颜色探针页验证
