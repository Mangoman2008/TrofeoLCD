# JPEG 质量 ↔ 字节 ↔ 帧率（实测）

- 主题 15 · 背景 `image` · `burst=1` · auto fps
- 采样：每档 6 次、间隔 3s
- 环境：负载 27.0（仅记录，不作门禁）; encode 61ms
- 复现：`python3 tools/measure_quality.py --out docs/质量曲线.md`

## ⚠️ 本文数据的可靠性声明（必须读）

本次采样是**单轮**的，而机器负载在采样期间**持续恶化**：
采样开始时 `encode` 61ms（正常），采样结束后复测同一批 q 值已经全部变成 **2100~3500ms**。

**因此下面"q<0.8 出现 encode 悬崖"这个现象，目前只能算"疑似"、尚未证实：**
- 支持它的是：q≥0.8 那 4 档的 `encode` 都很稳（58~68ms），而 q≤0.7 突然 614ms+
  —— 10 倍跳变不像纯噪声；
- 反对它的是：我在负载升高后重测 q=0.9 与 q=0.7，**两者最小 encode 都是 3.5 秒级**
  （3544~3733ms），悬崖分辨不出来。

**结论**：**需要在一台真正空闲的机器上重跑一次**才算定论：
```bash
python3 tools/measure_quality.py --out docs/质量曲线.md
```
（工具已把门禁改为"实测 encode 耗时"，超过 160ms 直接拒绝测量，避免再产出这种半可信数据。）

## 采样时的原始观察：降质量疑似负收益，且疑似有个悬崖

| 区间 | encode 实测 | 判定 |
|---|---|---|
| **q ≥ 0.8** | **58~68ms**（稳定） | ✅ 安全区。字节 37.6~56.2KB |
| **q < 0.8** | **614 → 1651ms**（暴涨 10~24 倍） | ❌ **绝不能用** |

**（疑似，待空闲机器复核）**：q 从 0.8 降到 0.7，字节只省了 4.7KB（37.6→32.9K），
而 `encodeMs` 从 **68ms 飙到 614ms**。

**机制推断**：鸿蒙的 JPEG packer 在较低质量档位会切到一条**更慢的编码路径**
（可能是更重的熵编码优化/多趟扫描），代价远超省下的那点字节。

**但无论悬崖是否成立，第 3 条路都走不通** —— 因为已确证的部分是：
**降 q 省下的字节很有限（46KB → 22KB）且与 push 耗时几乎无关**（见文末），
而 encode 才是帧时间的大头。
- 省字节要靠降 q；
- 但降 q 会把 encode 从 68ms 抬到 600ms+；
- 而 encode 才是帧时间的大头（push 只有 58~69ms）。

**正确做法**：**把质量钉在 0.85~0.9**（本工程当前默认 0.95 也安全），
要压帧时间只能从**像素量**下手（降采样渲染），而不是质量。

## 已确证（不依赖机器负载的部分）

### 1. 字节数确实随质量单调下降
46.0KB（q=0.95）→ 22.1KB（q=0.4），**趋势确定**。但幅度有限：
**q 从 0.95 降到 0.8 只省 8.4KB（18%）** —— 因为这个画面主要是文字与渐变，JPEG 对它本来就不敏感。

### 2. push 耗时与字节数**几乎无关**
同一主题、不同版面（字节 25~44KB）实测 push 耗时：

| 字节 | push |
|---|---|
| 40.1KB | 87ms |
| 44.0KB | 129ms |
| 37.0KB | 56ms |
| **25.2KB** | **135ms** |
| 39.7KB | 117ms |

**25.2KB 反而最慢（135ms）** —— 所以 push 耗时由**每帧固定开销 + 写次数 + 调度抖动**主导，
不是字节总量。这意味着"省字节换帧率"在 USB 这一侧本来就没什么空间。

### 3. 帧时间的大头是 encode，而 encode 取决于**像素量**（1920×462 恒定）
质量参数碰不到它。想压只能**降采样渲染**（会牺牲清晰度，与用户此前"字虚"的诉求冲突）。

## 最终建议

| 项 | 取值 | 理由 |
|---|---|---|
| JPEG 质量 | **0.9**（当前默认 0.95 亦安全） | 避开疑似慢路径，且字节已在合理区 |
| `burst` | **1** | 实测 5 → 15fps（唯一验证过的大收益） |
| fps | **auto（不设）** | 策略在 busy 档用 66ms，是它自己的安全值 |
| 压帧时间 | **只能降采样**，不能降质量 | encode 取决于像素量 |
